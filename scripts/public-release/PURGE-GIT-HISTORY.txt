If installers, secrets, or other files were EVER committed while the repo was public,
removing them from the latest commit is NOT ENOUGH — they remain in clone history until purged.

Options (pick one):

  A) New history (simplest): create a NEW repo (or orphan branch), copy only intended files,
     push as initial commit, archive the leaked repo name.

  B) git-filter-repo (recommended purge): install from https://github.com/newren/git-filter-repo
     Example — drop all committed .exe under releases/:

       git filter-repo --path-glob 'releases/*.exe' --invert-paths

     Then: git push origin --force --all && git push origin --force --tags
     Warn collaborators: force-rewrite affects everyone.

  C) GitHub "Report a vulnerability" / support for sensitive credential leaks if keys were pushed.

Wire this into your privatization checklist alongside making the repo private.
