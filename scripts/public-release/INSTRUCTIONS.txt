Why the public repo used to show "everything"
==============================================
GitHub publishes every file that is committed to the repo. Your development repo
had the whole Electron project + history pushed to the *public* remote, so
clones downloaded the entire source tree.

Goal: separate remotes / repos
------------------------------
PRIVATE repo (recommended):
  • Full Windows App source, scripts, workflows, proprietary LICENSE, etc.

PUBLIC repo (customers only):
  • README.md — short download + verify + link to site (use the template copied by the sync script)
  • releases/CommunityWatch-Setup-<version>.exe
  • releases/CommunityWatch-Setup-<version>.exe.sha256
  Nothing else unless you consciously add it.

Concrete steps on GitHub
------------------------
1) Create a NEW empty public repo, e.g. "CommunityWatch-Windows-Releases".

2) On your CURRENT repo (full source): GitHub Settings → Change visibility → Private.

3) Clone ONLY the empty public repo to a folder next to your private clone.

4) After `npm run dist:nsis` in the PRIVATE repo:

      set PUBLIC_RELEASE_DIR=C:\path\to\CommunityWatch-Windows-Releases
      npm run release:public

5) Inside the PUBLIC clone: git add, commit, push.

Optional: automate public pushes from CI in the PRIVATE repo using a PAT
scoped to push to the public repo only (narrow permissions).

Purging leaked binaries from Git HISTORY
----------------------------------------
If installers or secrets were EVER committed while the repo was public,
removing them from the latest commit is NOT ENOUGH — they remain in clone
history until purged.

  A) Simplest: NEW repo (or orphan branch), single clean commit, archive the old name.

  B) git-filter-repo: https://github.com/newren/git-filter-repo
       git filter-repo --path-glob 'releases/*.exe' --invert-paths
     Then: git push origin --force --all && git push origin --force --tags

  C) Rotate leaked credentials; use GitHub reporting for active secret leaks.
